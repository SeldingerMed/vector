# v0.3 framework and migration guide

**Status:** implemented in `0.3.0a0`.

## Goal

Make OR-Audit an independent evaluation framework for **procedural medical intelligence**. The unit of evaluation is a safety-constrained procedural trajectory through a world. Procedures remain task-owned data, never kernel branches.

## Keep without weakening

- Immutable `org/name@version` taskset, task, and agent packages; package digests; pinned worlds; self-contained bundles; deterministic replay; audit heads.
- Task-owned vector verifiers; hard gates separate from metrics; abstention and unassessable outcomes; no implicit scalar conversion.
- PHI class, de-identification/attestation boundaries, claim footers, and the existing registry, scorecard, cartesian-job, Lumen, video-nextstep, and AngioStress flows.
- Harbor/Prime-compatible concepts and CLI verbs without either framework as a dependency.

## Migrate

| v0.2 | v0.3 |
|---|---|
| `DatasetSpec` as the public concept | `TasksetSpec`; retain `DatasetSpec` as a schema-compatible name during v0.3 |
| `PortId` equality | task `InterfaceSpec` requirements satisfied by agent `CapabilitySpec` declarations; legacy ports translate during loading |
| closed agent-kind taxonomy | package-authored agent-kind slugs constrained by task-owned accepted kinds |
| world fields plus ad hoc input files | `WorldSpec` + explicit `HarnessSpec` + versioned `ScenarioSpec` and `PerturbationSpec` |
| `tuple[dict[str, Any], ...]` trajectory | typed `ProceduralTrace` with observation, output, action, transition, safety, uncertainty, failure, recovery, abstention, evidence, tool, handoff, and timing fields |
| bool/float metric values and truthy headline counts | typed boolean, continuous, and categorical outcomes with units, directionality, and kind-appropriate aggregates |
| local weights-only agents | pinned runtime descriptors for local, Hugging Face, API/OpenAI-compatible, and container execution |
| in-process submitted plugins | subprocess JSON protocol with separate agent/verifier views; no labels/oracles in the agent request |
| closed `ProjectionId` enum | versioned declarative `ProjectionSpec`, digest-pinned and recomputed from the authoritative vector |
| two runner branches by port | harness dispatch by interaction mode: closed-loop, interactive, single-turn, and counterfactual |

## Smallest coherent implementation

1. Add frozen schema models for interfaces/capabilities, scenarios/perturbations, typed traces, failure/handoff events, runtime identity, metric definitions, and projection rules. Accept v0.2 package fields and normalize them into the v0.3 model.
2. Change binding to capability satisfaction and make the old `gym-policy` / `video-predict` values compatibility aliases, not the extension boundary.
3. Add subprocess plugin execution with a JSON request/response contract. Give agents only observations/inputs; run verifiers separately with oracle evidence. Keep an explicit trusted in-process mode only for injected CI doubles.
4. Route execution by harness interaction mode. Preserve current Lumen and video/AngioStress behavior; add bounded multi-turn interaction and a counterfactual path for state + candidate interventions → predicted consequences/ranking.
5. Emit typed traces for every runner. Reconstitute vectors from typed trace evidence and keep bundle/head formats deterministic.
6. Aggregate metrics by declared kind. Add failure detection, recovery, safe abandonment, unsafe persistence, harm-after-failure, abstention, and handoff outcomes without producing an overall score.
7. Replace enum-based RL export with a versioned declarative projection whose digest and rule are exported beside the reward. Safety gates remain authoritative and can force projection refusal/zero.
8. Upgrade examples: Lumen carries declared scenario/perturbation metadata into typed traces; video demonstrates structured reasoning plus abstention; counterfactual scenarios demonstrate failure, recovery, safe abandonment, uncertainty, and evidence references.
9. Update README, PRODUCT, BUILD, ASSESSMENT, fixtures, scorecards, registry-compatible loaders, and migration guidance. Add invariant and compatibility tests, run the complete lint/type/test matrix, smoke-run the three packaged reference paths, and exercise interactive run/replay end to end.

## Explicit limits

- No procedure, anatomy, specialty, or device enum in the kernel.
- No hosted multi-tenant service, ROS/hardware execution, or generic sandbox platform in v0.3. Their runtime descriptors and extension points are represented; only the minimum safe local/subprocess execution path is implemented now.
- No scalar leaderboard. Projection/reward artifacts remain secondary, versioned derivatives of the full published vector.

## Package migration

New task packages declare `[interface]` and `[harness]`. The interface contains protocol and schema requirements; the harness selects one of `closed-loop`, `interactive`, `single-turn`, or `counterfactual`. Interactive items carry bounded ordered `turns`; the persistent agent receives prior observation/output history but never labels. `[[scenarios]]` and `[[perturbations]]` are versioned task-owned records.

New agent packages declare one or more `[[capabilities]]` and a `[runtime]`. A capability must satisfy the task's interaction mode, protocol version, observation schemas, action or output schemas, and required features. A runtime descriptor pins execution identity independently of model weights.

Task collections use `taskset.toml`:

```toml
format_version = "2"
id = "org/taskset"
taskset_version = "1"
headline = "safe_success"
phi_class = "procedural"
tasks = [\"../tasks/example\"]
```

The loader accepts v0.2 `port`, `dataset.toml`, `dataset_version`, untyped metrics, entrypoint fields, and list-shaped trajectories. It normalizes them before canonical validation. `or-audit datasets` and `run -d` remain CLI input aliases; new automation should use `tasksets` and `run -s`.

An optional `[stage]` block turns an existing Cartesian `job.toml` into one
provider-neutral gated stage. The runner requires `target_units` to equal
the observed `unit_source`: `trials`, `trajectory-steps`, or the summed integer
value of a task metric such as `metric:sample_count`. It checks scenario and
event names against the selected task packages, then writes the target,
observed count, and aggregate gate outcome into the manifest head.
`independent_cases` is deliberately separate from execution
units. The runner recomputes it from `independent_case_key` (`$seed` for a
closed-loop stage, or an input-item field such as `sequence_id`), counts the
same cases only once across compared agents, and rejects missing or inflated
claims. Dataset-backed runs also reject `n` above the available input count;
nested frames, perturbations, and timesteps cannot masquerade as extra trials.
Jobs with unequal scenario budgets use `task_trials = { "path/to/task-a" = 30,
"path/to/task-b" = 1 }`; its keys must exactly match `tasks`. A job may declare
either global `n` or `task_trials`, never both.

```toml
[stage]
name = "qualification"
evaluation_unit = "seeded simulator episode"
unit_source = "trials"
target_units = 10000
independent_case_unit = "anatomy-target seed"
independent_case_key = "$seed"
independent_cases = 10000
scenarios = ["nominal", "severe-stenosis"]
event_injections = ["sensor-dropout"]
operator_contexts = ["autonomous", "supervised"]
stop_conditions = ["stop on any hard gate failure"]
prerequisites = ["integration-smoke", "pilot"]
```

The public runner executes and attests one stage. Scheduling later stages,
capacity provisioning, billing, and tenant policy remain outside this public
evaluation contract.

## Artifact migration

Job format `2` adds interface, interaction mode, runtime identity, projection identity, and per-trial projection-rule digest. `trajectory.json` stays a JSON array for portable v0.2 readers, and legacy rows normalize into typed `TraceStep` records when loaded. Scorecards aggregate by declared metric kind and display execution identity. Leaderboards rank fewer hard-gate failures first, order boolean/continuous headlines only by declared direction, and leave categorical headlines unranked. RL rows carry the complete projection rule and its digest. Registry input accepts v0.2 `datasets` / `kind="dataset"` and normalizes them to tasksets.

Replay remains the migration gate: load the old package, run it through the v0.3 adapter, reconstruct vectors from the stored trace, and require the same stamped head on rerun.
